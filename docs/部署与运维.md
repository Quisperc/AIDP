# 部署与运维

> 面向「要发版 / 要排障」的场景。架构背景见 `docs/架构说明.md`，
> 服务器侧的目录与容器约定见 `deploy/README.md`。

## 一、生产拓扑

| 组件 | 位置 | 对外地址 |
|---|---|---|
| 认证中心 + 管理台 | 容器 `idp_auth_server`，`127.0.0.1:18090 → 8080` | `https://idp.civer.cn` |
| 数据库 | 1Panel PostgreSQL，库 `idp_auth_db` | 内网 |
| 缓存/会话 | 1Panel Redis（可选） | 内网 |

管理台在 `/admin`，与认证中心同域同进程，**没有第二个容器、没有独立的前端部署**。

jar 由 1Panel「Java 运行环境」托管：`/home/idp/auth_server` 挂载到容器 `/app`，`run.sh` 执行 `java -jar`。

## 二、环境变量

改 `/opt/1panel/runtime/java/idp_auth_server/.env` 后 `docker restart idp_auth_server` 生效，
**不需要重新构建 jar**。

| 变量 | 作用 | 生产值 |
|---|---|---|
| `APP_BASE_URL` | 决定 OIDC `issuer`，必须是对外地址 | `https://idp.civer.cn` |
| `FLYWAY_ENABLED` | 是否执行库迁移 | `true` |
| `SESSION_STORE` / `CACHE_TYPE` | 单机留空，多实例设 `redis` | 视部署 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | Redis 连接 | 按实际 |
| `APP_BOOTSTRAP_SEED_DEMO_USERS` | 是否创建演示账号 | **`false`** |
| `ACCESS_TOKEN_TTL` | 新注册客户端的 access token 有效期 | `30m` |

> 只改 `APP_BASE_URL` 而不同步更新各子系统的 `issuer-uri`，会导致 Back-Channel 验签失败
> （现象：全局登出时其它系统不退）。

## 三、本地构建与自测

```bash
mvn clean package      # 含 27 个回归测试
mvn test               # 只跑测试
```

测试用 H2 + Flyway，不依赖外部 PostgreSQL，可离线重复执行。

## 四、发布通路

```
本地 commit
  → git push origin main / git push origin auth-vX.Y.Z
    → GitHub Actions「Sync to CNB」（.github/workflows/sync-cnb.yml）
      → CNB 仓库收到 tag
        → CNB 流水线（.cnb.yml）
          → 构建依赖缓存镜像 → 测试 + 构建 + 发布制品 → rsync → 重启 → 健康校验
```

**标签即发布开关**：

| 标签 | 行为 |
|---|---|
| `auth-v2.4.0` | 构建并部署认证中心（含管理台） |
| 其它（如 `v1.2.3`） | 不触发，**不会发布** |

版本号必须三段式（`X.Y.Z`），否则构建阶段第一行就报错退出。

### 每个环节怎么确认它成了

| 环节 | 确认方式 |
|---|---|
| GitHub → CNB（标签） | Actions 页面该 run 的「1) 同步标签」为绿色 |
| GitHub → CNB（分支） | 同上「2) 同步分支」；`git ls-remote --heads cnb` 与 `origin` 一致 |
| CNB 构建 | 阶段 2 结束能看到 `BUILD SUCCESS` 与 `Auth-Server.jar` |
| CNB 制品 | `https://maven.cnb.cool/civer/cnb-maven/-/packages/` 有对应版本 |
| 部署 | 阶段 3 日志末尾 `health UP http://127.0.0.1:18090/actuator/health` |

### 日常发版

```bash
git tag auth-v2.4.0 && git push origin auth-v2.4.0
```

构建阶段会跑完整测试，测试不过就不会产出 jar、也不会部署。
制品推送 CNB Maven 库是「尽力而为」：同版本不允许重复发布，重跑旧标签做回滚时
这一步会失败并自动退回本地构建，不影响部署。

## 五、镜像同步故障：`non-fast-forward`

这条链路唯一一次真正断掉的原因，务必认识它。

**现象**：GitHub Actions 的 `Sync to CNB` 连续失败，日志里是

```
! [rejected]  main -> main (non-fast-forward)
error: failed to push some refs to 'https://cnb.cool/civer/Quisperc/AIDP.git'
```

**根因**：CNB 侧 `main` 有 GitHub 没有的提交（历史被重写、或有人在 CNB 上直接提交），
两边分叉，普通 push 被拒。

**后果**：早期实现把「推分支」和「推标签」放在同一步，分支失败整步退出，
**标签也永远不会推到 CNB**，于是一次发布都不会发生，而 GitHub 只是把 run 标红。

**现在的防护**：workflow 拆成两步，标签先推、分支后推。分支再分叉也只影响镜像完整性，
不会阻断版本发布；同时分支失败仍然是红灯。

**一次性修复分叉**（确认 CNB 侧没有需要保留的提交后）：

```bash
git fetch origin
git push cnb origin/main:main --force
git ls-remote --heads origin main
git ls-remote --heads cnb main      # 两个 SHA 应一致
```

> 预防：在 CNB 仓库把 `main` 设为保护分支，禁止直接推送与在线编辑，只作 GitHub 的只读镜像。

## 六、发布后验证清单

- [ ] `https://idp.civer.cn/.well-known/openid-configuration` 的 `issuer` 正确
- [ ] `https://idp.civer.cn/actuator/health` 返回 `UP`
- [ ] 匿名访问 `https://idp.civer.cn/admin/users` 跳登录页；登录后能打开列表
- [ ] 普通用户（`user`）登录后访问 `/admin/users` 返回 403
- [ ] 浏览器走一遍：登录 → 用户列表 → 新建用户 → 客户端列表 → 注册客户端 → 账号页
- [ ] 退出后其它子系统的会话也被清掉（验证 Back-Channel 广播）
- [ ] 日志无 `ERROR`：`docker logs --tail 200 idp_auth_server`

## 七、回滚

```bash
# 方式 A：重新发布上一个标签（推荐，可追溯）
git push origin :refs/tags/auth-v2.3.9     # 删除已存在标签
git tag auth-v2.3.9 <上一个 commit>         # 重建
git push origin refs/tags/auth-v2.3.9      # 重新触发构建与发布
```

方式 B（手工替换 jar + 重启）与更完整的说明见 `deploy/README.md` 第五节。

> 流水线不保留历史 jar，回滚必然要重跑一次构建。若要一键回滚，需要把服务器上的
> `Auth-Server.jar` 改成指向 `releases/<version>/` 的软链，属于运维改造，尚未执行。
