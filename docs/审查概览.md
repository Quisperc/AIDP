# AIDP 代码审查 · 工作概览

## 做了什么

拉取 `github.com/Quisperc/AIDP`（git 直连失败，改用 codeload 下载 zip 成功），对全部 72 个文件做了逐文件审查，产出优化方案。

项目画像：Spring Boot 4.0.3 + Java 22 的 OIDC 统一认证系统，三模块结构
- `auth-server`（8080）认证中心
- `client-usermanage`（8081）管理后台
- `client-template`（8089）接入模板

规模：Java ~2650 行 · HTML ~4300 行 · 零测试 · 无前端工程

## 关键发现

**2 个 P0 级安全问题**
1. `AuthServerApplication` 缺 `@EnableMethodSecurity` → auth-server 中所有 `@PreAuthorize("ROLE_ADMIN")` 静默失效。任意登录用户可创建管理员、改他人密码、删客户端。（client-usermanage 侧有该注解，是正常的）
2. `RevocationController` 的 `redirect_uri` 零校验 → 开放重定向钓鱼

**1 个架构硬伤**
RSA 密钥每次启动内存随机生成 → 重启即全员掉线 → 无法多实例水平扩容

**前端（用户重点关切）**
- 没有前端工程（无 package.json / 无独立 css/js），15 个 Thymeleaf 模板样式全内联
- 内联 CSS 2879 行，**重复率 75.9%**（去重后仅 694 行）
- **14/15 页面加载 Google Fonts**，国内首屏被阻塞
- 但设计语言其实统一（仅 4 套渐变色），抽取成本低

**精简空间**
- 两个客户端 `SecurityConfig` + `SsoLogoutController` 逐字符重复，517 行 → 抽 starter 后净减 ~320 行
- 36 处 `System.out.println`、353 处行内全限定类名、零 `@Transactional`、零索引

## 产出

- `AIDP-优化方案.md` —— 完整方案（含代码级修复、量化收益表、12 项路线图）

## 核心建议

最该立刻做的两件事：
1. 加一行 `@EnableMethodSecurity` —— 堵住越权漏洞
2. 前端 CSS 外链化 + 去 Google Fonts —— 两天工作量，减 72% 样式代码，**不动一行 Java**

## 注意事项

- 修复第 1 条后权限会"突然生效"，需先验证 admin 的 `roles` claim 链路，建议测试环境验证后灰度
- 建议 auth-server 的登录页/授权同意页**保持服务端渲染**（OAuth2 规范要求），只对管理后台考虑 SPA 化
