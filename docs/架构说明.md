# 架构说明

> 讲清楚三件事：系统由哪些部分组成、登录/退出怎么走、为什么是现在这个样子。

## 一、一个应用就够了

| 部分 | 形态 | 说明 |
|---|---|---|
| 认证中心 | Spring Boot 单体 | OIDC 提供方 + 管理台 + 登录页 |
| 管理台 | Thymeleaf 服务端渲染 | `/admin/**`，会话 + `ROLE_ADMIN` |
| 子系统 | 各自独立部署 | 标准 OIDC 客户端，不碰认证库 |

历史上有过一版「认证中心 + 独立管理端（8081）+ Vue SPA（EdgeOne）」的三段式：
管理端不持有数据，靠带令牌转发调用认证中心的 `/api/**`，前端跨域托管。

那个结构能跑，但它要让**同一个进程给同一个进程发令牌**：IdP 认证用户 → 签发 token 给
管理端 → 管理端拿 token 回来校验 IdP 自己的接口。这个环回不带来任何安全隔离
（管理 API 本来就在 IdP 上），却额外引入五套机制：

- 令牌获取、持久化与过期重登（`RedisOAuth2AuthorizedClientService`）
- 跨域会话（`SameSite=None` + CORS 白名单 + CSRF cookie 跨站回传）
- 登出广播的接收端（自己给自己发 logout_token）
- 前端构建与独立部署（Node 工具链、产物上传、SPA 路由回退）
- 两份 DTO、两份配置、两套环境变量

现在这些全部不存在了。代价是管理台失去 CDN 与前后端独立迭代，换来的是：
一个 jar、一个容器、一条流水线、一套技术栈。

## 二、登录

**管理员/用户进管理台**：普通的表单登录。

1. 访问 `/admin/**` → 未认证 → 重定向 `/login`
2. 提交账号密码 → `DaoAuthenticationProvider` 校验 → 写入 `AUTH_SESSIONID` 会话
3. 登录成功处理器优先回到被拦截的那个地址（`SavedRequest`），否则回 `/`

**子系统接入**：标准授权码 + PKCE，用户代理与认证中心同源交互，这是 OAuth2 的硬要求，
所以登录页与同意页必须服务端渲染，不能做成 SPA。

1. 子系统发现未登录 → 重定向 `{idp}/oauth2/authorize?client_id=...`
2. 认证中心若无会话 → 跳 `/login`；已登录但未同意 → 跳 `/oauth2/consent`
3. 同意后回调子系统，子系统用 code + secret 换 token

`roles` claim 由 `TokenConfig.jwtTokenCustomizer()` 写入 access token ——
这一步只服务于**其它子系统**读取角色；管理台用会话直接拿 authorities，不经过 token。

## 三、退出（只用标准端点）

认证中心不提供自研的登出/撤销接口，全部走 OAuth2 / OIDC 与 Spring Security 的标准入口：

| 入口 | 规范 | 谁用 | 行为 |
|---|---|---|---|
| `POST /logout` | Spring Security 表单登出（带 CSRF） | 管理台页面上的「退出」 | 清会话 → 全局退出 |
| `/connect/logout` | OIDC RP-Initiated Logout（discovery 的 `end_session_endpoint`） | 外部系统 | 全局退出；`id_token_hint`、`post_logout_redirect_uri` 由框架校验 |
| `POST /oauth2/revoke` | RFC 7009 Token Revocation | 外部系统后端 | 撤销单个 token（客户端凭证认证） |

**全局退出**（两个入口共用同一段逻辑，实现在 `SsoLogoutService`）做两件事：

1. 删该用户的全部 `oauth2_authorization_consent`；
2. 删该用户的全部 `oauth2_authorization`——即吊销 access / refresh / id token。

不再向子系统推送私有登出消息：客户端本地会话由应用自行按 RP-Initiated Logout 结束，
或在令牌失效后自然退出。认证中心只负责令牌生命周期，不做私有协议扩展。

第 2 步是关键：只删 consent 的话，客户端手里的 refresh_token 在有效期内仍能静默续期，
用户看到「已退出」，实际只是不会再弹同意页。

表单登出的挂点是 `SsoLogoutSuccessHandler`；OIDC 登出的挂点是给
`OidcLogoutAuthenticationSuccessHandler` 设一个 `LogoutHandler`——回跳地址与
`id_token_hint` 的校验都留给框架，避免自己实现时漏掉。

**单点退出（只退某个应用）不需要 IdP 参与**：子系统清掉自己的会话即可完成退出，
IdP 保留同意记录反而让用户下次免于再点一次同意。若确实要让该应用的令牌立即失效，
用它自己的 `client_secret` 调 RFC 7009 的 `/oauth2/revoke`（后端 POST，不经浏览器）。

> 2026-11 之前这里还有两个自研端点：`/oauth2/logout-all`（与 `/connect/logout` 功能重叠）
> 和 `/oauth2/revoke-consent`（标准里没有对应物，但也并非必需）。两者已删除，
> 管理台改密后的强制下线改为**在同一请求内直接调用服务**，不再 302 到自研 URL。

## 四、密钥、会话、缓存

| 关注点 | 无 Redis 环境 | 生产（Redis 已启用） |
|---|---|---|
| JWT 签名密钥 | `oauth2_signing_key` 表，启动读或生成 | 同左，全实例共享 |
| HTTP Session | Servlet 容器本地（排除自动配置后） | Redis，namespace `aidp:auth` |
| 登录失败计数 | `ConcurrentMapCacheManager` | `RedisCacheManager`，跨实例共享 |

签名密钥落库是关键：早期每次启动随机生成，导致「重启即全员掉线」且多实例互相验不了签。
密钥损坏时启动直接失败，不静默重建（重建会让已签发令牌全部作废）。

会话 Cookie 刻意**不设 domain**：OIDC 下各客户端自己管自己的会话，认证中心不需要把 cookie
发到所有子域。设成 `.civer.cn` 只会扩大泄露面，并让本地 127.0.0.1 调试时会话存不下来。

## 五、Redis 会话与缓存（生产默认启用）

Spring Boot 4 起 `spring.session.store-type` 已移除：**classpath 上有
`spring-boot-starter-session-data-redis` 就自动把 HttpSession 存进 Redis**，不再有环境变量开关。
store 专属属性的前缀是 `spring.session.data.redis.*`——写旧的 `spring.session.redis.*`
会被静默忽略，namespace 退回 `spring:session`，与共享 Redis 上的其它应用串键。

`application.yml` 里的落地值：

```yaml
spring:
  session:
    data:
      redis:
        namespace: aidp:auth          # 与其它应用隔离
        repository-type: default
        configure-action: none       # 共享 Redis：不擅自 CONFIG SET 改全局配置
  cache:
    type: ${CACHE_TYPE:simple}        # 生产设 redis，跨实例共享登录失败计数
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      password: ${REDIS_PASSWORD:}
```

生产 `.env` 只需 `CACHE_TYPE=redis`、`REDIS_HOST`、`REDIS_PASSWORD`（不再有 `SESSION_STORE`）。
Redis 侧须保持 `notify-keyspace-events=Egx`——Spring Session 靠它接收会话过期事件；
`configure-action: none` 表示由 Redis 侧统一配置，应用不改全局设置。

无 Redis 的环境（集成测试、纯本地调试）在 profile 里排除自动配置：

```yaml
spring:
  autoconfigure:
    exclude: org.springframework.boot.session.data.redis.autoconfigure.SessionDataRedisAutoConfiguration
```

所有实例必须连**同一个库**：`issuer`、签名密钥、客户端注册表都要一致，否则 id_token 验签失败。

## 六、已知取舍

| 项 | 现状 | 影响 |
|---|---|---|
| 管理台与 IdP 同域同进程 | 管理面被攻破即等于 IdP 被攻破 | 试运行阶段可接受；真要隔离应拆成独立进程 + 独立库，而不是原来的半隔离 |
| `DELETE /admin/users/{id}` 实为停用 | 只置 `enabled=false` | 按钮文案写的是「停用」，保留授权与审计痕迹是有意为之 |
| 管理台列表每页 20 条 | 页码走 `?page=N`（0 基），越界回落到最后一页 | 百级数据够用；上千条时还需要加搜索与筛选 |
| 操作审计记管理台与账号自助的写操作 | 表 `admin_audit_log`，页面 `/admin/audit`（仅管理员可见），只追加 | 含普通用户的 `ACCOUNT_UPDATE` / `AUTHZ_REVOKE`；不记登录事件（归 `[login-guard]` 日志） |
| 登录失败限流按用户名 | 默认 10 次 / 15 分钟，管理员豁免 | 管理员被锁后没有自助解锁入口，故不参与限流，改用强口令 + 审计覆盖 |
| 最后一个启用中的管理员受保护 | 停用/降级会被服务端拒绝 | 避免误操作把所有人挡在管理台外；换管理员需先给他人授权 |
| 无指标监控 | Actuator 只暴露 health/info | 排障靠日志，日志带 `[users]` `[clients]` `[sso-logout]` 前缀便于检索 |
