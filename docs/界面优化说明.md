# 界面视觉与可用性优化说明

> 范围：`idp.civer.cn`（认证中心）、`admin.civer.cn` / `um.civer.cn`（管理后台，同一份前端源码）。
> 约束：**不改任何功能与交互逻辑**——接口调用、路由守卫、表单字段与提交地址、CSRF、OAuth2 参数、scope 勾选逻辑、退出流程全部原样保留，只动视觉与文案。
> 改动文件：16 个（Vue 7 / CSS 4 / Thymeleaf 5）。

## 一、现状诊断：问题不在于"不好看"，而在于"结构坏了"

改造前用真实产物 + 真实接口数据做了渲染走查，最严重的问题不是配色，而是**布局错位**：

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| 1 | **整站内容被压成约 320px 宽的一列**，1440px 屏幕上右侧 70% 是空白 | `App.vue` 的 `main` 是 column flex，`.page` 用 `margin: 0 auto` + `max-width`；flex 子项的 auto margin 会取消拉伸，元素变成 shrink-to-fit | 342px 的表单挤在 1080 的版心里；概览页两张卡片被迫竖排；表头与内容全部收缩到不可读 |
| 2 | **客户端列表文字重叠**："回调地址"的 URL 压到 PKCE 徽标上 | `td` 上 `max-width:320px` + mono 不换行，表格又只有 640px 可用宽度 | 用户看不到完整 redirect_uri，而这是接入时最容易配错、最需要逐字符核对的字段 |
| 3 | 正文/链接对比度不达标 | `#007aff` 在 `#f2f2f7` 上 **3.6:1**（AA 要求 4.5）；`label-secondary` 仅 **3.44:1**；`#34c759` 当正文 **2.22:1**；`#ff3b30` **3.55:1** | 表格与导航的次要文字在普通屏上"发灰"，错误提示偏粉难读。讽刺的是 tokens 注释里写着"满足 WCAG AA" |
| 4 | 备案号几乎不可见 | 页脚 `--label-tertiary` = rgba(60,60,67,.3)，白底 **1.74:1** | 合规信息被做成了装饰，等于没展示 |
| 5 | 按钮重量混乱 | 表格里"删除"是 28px 文字按钮，弹窗里"删除"是 36px 红色实色；"编辑"是灰底胶囊 | 危险操作在列表里反而比在确认框里更轻，用户容易误点/难判断 |
| 6 | 弹窗必溢出 | 客户端表单 6 个字段，`.modal` 无 `max-height`，body 无滚动 | 768px 高的笔记本上，"保存"按钮直接落在视口外，只能靠 Esc |
| 7 | 触控目标过小 | `.btn-sm` 28px、导航链接 26px | 触屏（平板/手机）误触率高 |
| 8 | 认证中心全英文，管理后台全中文 | `Welcome Back / Sign In / Authorization Required / Login Successful!` vs `概览 / 用户 / 客户端` | 同一产品的两个入口语言割裂；且"Welcome Back"对首次登录不成立 |
| 9 | 登录页没有产品名 | 只有一个 52px 蓝色人形图标 | 用户在输入密码前无法确认"这是哪个系统"，这是反钓鱼的第一道视觉线索 |
| 10 | 图标是页面上最重的色块 | 52×52 纯 `#007aff` 方块 + 白图标 | 抢走主按钮的焦点，主次颠倒 |
| 11 | 中文字号阶梯照搬 iOS | `--fs-body: 17px`，控件全用 15px，标题 34px | 34px 中文标题笨重、17px 在表格里撑散；中文需要更紧的字阶（15/14/13）与更大行高 |
| 12 | 间距名不副实 | "8pt 网格"下出现 `margin-top: 2px`、`padding: 2px 8px`、`margin-top: calc(-1 * var(--sp-2))` | 节奏不齐，负边距补偿是结构性坏味道 |
| 13 | 主题切换用字符 `☀ / ☾` | 各平台字形差异极大，实际渲染成一个蓝点 | 用户认不出这是"切换主题" |
| 14 | 骨架屏与真实行高不符 | 4 条 22px 骨架 vs 40px 表格行 | 加载完成瞬间页面跳动 |

## 二、设计方向：从"通用后台模板"换成"凭证（Credential）"

身份认证系统真正处理的物件是**凭证**：一枚印记、一个可核验的编号、一条划出边界的细线。整套视觉从这里长出来，而不是从"任何后台都能套"的默认审美里取。

三条硬规则，落地在代码里：

1. **一个墨蓝，一个实色按钮**。`--brand: #2b49c8`（白底 7.27:1）。一个界面只允许一个实色填充按钮，其余退为描边或纯文字——"下一步该点哪里"永远没有歧义。
2. **语义色只做"点 + 浅底 + 深字"三层**。绝不用 `#34c759` 这类高饱和色本身写正文（2.22:1 ≈ 不可读）。状态 = 6px 圆点 + 文字，颜色只承担"是什么状态"，不承担"能不能读"。
3. **数字与 ID 用等宽 + tabular-nums**。用户名、ID、redirect_uri、scope 需要被**逐字符核对**，不是被"读"的。

刻意避免的默认审美（自审记录）：
- 不用暖米色底 + 衬线大标题 + 陶土色；
- 不用近黑底 + 荧光绿；
- 不用 01/02/03 编号装饰（本产品没有"步骤序列"语义）；
- 不用全大写小标签（`text-transform: uppercase` 对中文是空操作，只是让英文列名和中文混排节奏错位）。

## 五、逐站改动

### 1. `admin.civer.cn` / `um.civer.cn`（同一份 SPA）

- **修复布局塌缩**：`.page` 加 `width: 100%`（保留 `max-width: 1160`）。这是本次**单点收益最大**的改动——一行 CSS 把"320px 挤压"恢复成完整版心。
- **概览页重构**：从"两张等宽卡片堆叠"改为"身份凭证卡（1.55fr）+ 可用功能卡（1fr）"。凭证卡用**细线网格（2×2）**呈 用户名 / 角色 / 认证方式 / 会话状态，底部虚线收口写会话说明。页面先回答"我是谁"，再回答"我能做什么"。
- **用户列表**：首列 ID 用等宽 + 三级色；用户名加首字母头像（`.avatar`）；角色用字重区分管理员（不再叠一层彩色徽标）；状态用圆点；"编辑"描边、"删除"纯文字红。
- **客户端列表**：redirect_uri 改为**单行省略 + “+n”** 并带 `title` 全文；彻底消除与 PKCE 列的重叠；窄屏隐藏 ID 列、表格最小宽度 640 → 520，一次短滑即可到"状态/操作"。
- **账号页**：表单卡 + 右侧"修改后会怎样"说明卡，把原先散落在底部的三句提示收拢成条目。
- **登录页**：加 AIDP 品牌件（标记 + 产品名）、锁图标说明"凭据不经过本系统"。
- **窄屏**：≤860 隐藏用户名、≤620 隐藏品牌文字与头像、导航横向滚动；导航项不再溢出。

### 2. `idp.civer.cn`（认证中心，Thymeleaf + `hig.css`）

- **文案全面中文化**：`Welcome Back → 登录`、`Sign In → 登录`、`Authorization Required → 授权确认`、`Cancel/Authorize → 拒绝/允许授权`、`Login Successful! → 已登录`；错误/退出提示改为界面口吻并给出下一步（"请联系系统管理员重置"）。
- **加品牌件**：每页顶部 `AIDP | 统一身份认证`，让用户在输密码前确认系统身份。
- **图标降重**：52px 纯蓝方块 → 44px 淡底描边块（`--brand-soft` + 品牌色图标），把重量让给主按钮。
- **授权同意页重构**：新增"当前登录"身份行；scope 列表由裸字符串改为**中文释义 + 原值等宽小字**（`openid → 确认你的身份`，`offline_access → 在你离线时保持登录状态`，未知 scope 回退原值）；补一句"取消勾选可能导致无法登录"。
- **布局修正**：`auth-card` 自带 `max-width: 440px`（原先用 `width:100%` 会在 grid 里撑满整行）；页脚备案号抬到次级色。
- **不动的**：`th:action`、`name="username/password"`、CSRF 隐藏域、`/oauth2/authorize` 表单、`client_id/state`、`th:each` 与 checkbox 的 `name/value`、`cancelConsent()` 与整行切换脚本，全部逐字保留。

## 七、部署注意

1. **前端需重新构建**，且必须带 `VITE_API_BASE=https://um.civer.cn`、`VITE_AUTH_SERVER_URL=https://idp.civer.cn`（生产是跨域部署）。
2. EdgeOne Pages 部署时 `workspacePath` 与 `builtFolderPath` 必须指向**同一个纯产物目录**（如 `pages-out/`），否则会回写 `.edgeone/` 里的旧产物——这个坑之前踩过。部署后核对首页引用的 JS hash 且该 JS 内含 `https://um.civer.cn`。
3. `idp` 需重新打 jar（只改了 `static/css/hig.css` 与 5 个模板）：`mvn -DskipTests package` → 替换 `/home/idp/auth_server/*.jar` → `docker restart`。
4. 两端都要提示用户强刷（`Ctrl/Cmd+Shift+R`），旧 `index.html` 会被浏览器缓存。

## 八、第二轮补充（2026-11-03 晚）

### 8.1 授权同意页整行点击：改为原生实现

上一版用 `pointer-events: none` 让点击穿透到行容器，靠脚本切换复选框。行为对了，但留下两个隐患：
label 与复选框的关联失效（点文字不再有原生语义）、文本无法选中。

本轮改回标准做法：整行就是一个 `<label>`，复选框在 label 内部。

```html
<li class="scope-item">
  <label class="scope-row">
    <input type="checkbox" name="scope" value="openid" checked>
    <span class="scope-body">…</span>
  </label>
</li>
```

- 删掉了 8 行切换脚本，点击行内任意位置（含空白与内边距）都由浏览器原生切换；
- 不会再出现"脚本与 label 各切一次互相抵消"；
- 键盘 Tab 聚焦复选框后按空格可用，`.scope-row:focus-within` 给整行左侧 2px 墨蓝标作为焦点提示。

### 8.2 列表搜索 / 排序 / 分页

用户与客户端两张表都加上了工具条、可排序表头与分页条，共用 `src/composables/useTable.ts`。

| 能力 | 用户表 | 客户端表 |
|---|---|---|
| 搜索 | ID、用户名、角色中文名、启用状态 | Client ID、名称、回调地址、是否强制 PKCE |
| 排序 | ID / 用户名 / 角色 / 状态 | Client ID / 名称 / PKCE |
| 分页 | 10 / 20 / 50 条每页，`上一页 / 下一页` + 当前页 | 同左 |

实现要点：

- **排序对全部行生效，而不是只排当前页**：先过滤、再排序、最后切片。
- 排序列用 `aria-sort` 标在 `<th>` 上，箭头按状态旋转；未排序列箭头压到 22% 不透明度，暗示可点又不抢注意力。
- 搜索无结果时在表内显示"没有匹配的用户 / 客户端 + 清空搜索"，与"一条数据都没有"的空状态区分开。
- 搜索词变化自动回到第 1 页；数据变少导致当前页越界时也回到第 1 页。
- **为什么放在前端**：接口目前返回全量数组（用户与客户端都在百级），一次算完翻页与搜索零延迟。若单表涨到数千行，把 `useTable` 里的 `paged` 换成服务端返回的当前页即可，组件层不用改。

### 8.3 顺手修掉的：客户端列表 PKCE 列是假的

之前每一行都显示"需查看详情"——因为列表走 SQL 投影，没取 `client_settings`，`requirePkce` 恒为 false。
本轮把该列加入投影并用正则解析 `"settings.client.require-proof-key": true`，
列表直接显示"强制 / 未强制"，未强制用警示色（这是安全基线，不该藏起来）。

### 8.4 构建不再手工补 404.html

新增 `scripts/postbuild.mjs`，`npm run build` 自动把 `dist/index.html` 复制为 `dist/404.html`。
之前这步是部署前手工 `cp`，CI 构建（EdgeOne 关联 Git 仓库）没法照做，现在打通了。
