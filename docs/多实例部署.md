# 多实例部署指南

> 默认（不设任何环境变量）就是单机模式，行为与改造前一致，不依赖 Redis。
> 需要水平扩容时按下表设置环境变量即可，代码无需改动。

## 为什么要做这些

改造前有三个地方把系统锁死在单实例：

| 问题 | 后果 |
|---|---|
| RSA 密钥在内存随机生成 | 重启即全员掉线；实例间密钥不同，互相验签失败 |
| HTTP Session 存在本地 Servlet 容器 | 请求打到另一个实例就变成未登录 |
| `SessionRegistryImpl` 是内存的 | `maximumSessions(1)` 只在单实例内生效，用户可在两个实例各登录一次 |
| host 白名单缓存是进程内的 | A 实例改了客户端，B 实例的缓存还是旧的 |

RSA 密钥已于前一轮落库到 `oauth2_signing_key`，本轮解决后三项。

## 单机模式（默认）

无需任何配置。此时：

- `spring.session.store-type = none`（本地会话）
- `spring.cache.type = simple`（ConcurrentMap，进程内缓存）
- `SessionRegistry` 用内存实现 `SessionRegistryImpl`

依赖里虽然有 Redis 相关 jar，但**不会尝试连接 Redis**——连接工厂是懒初始化的，
只有 `store-type=redis` / `cache.type=redis` 时才会真正使用。

## 多实例模式

两个模块（认证中心、管理后台）都要设置：

```bash
SESSION_STORE=redis
CACHE_TYPE=redis
REDIS_HOST=redis.internal
REDIS_PORT=6379
REDIS_PASSWORD=<your-password>
```

对应的行为变化：

| 组件 | 单机 | 多实例 |
|---|---|---|
| HTTP Session | Servlet 容器本地 | Redis（Spring Session） |
| SessionRegistry | `SessionRegistryImpl` | `SpringSessionBackedSessionRegistry` |
| host 白名单缓存 | ConcurrentMap | RedisCacheManager（任一实例失效，全体可见） |

`SessionRegistry` 的切换在 `SessionRegistryConfig`，两个实现由
`spring.session.store-type` 互斥选择。这一环最容易漏：**只共享 Session 而不换
SessionRegistry，单设备登录仍然是假的**。

## Redis 侧的准备

管理后台配置了 indexed session repository：

```yaml
spring.session.redis:
  repository-type: indexed
  configure-action: configure_keyspace_notify_events
```

`indexed` 是必需的——它会创建 `FindByIndexNameSessionRepository`，
`SpringSessionBackedSessionRegistry` 靠它按用户名查该用户在所有实例上的会话。

`configure_keyspace_notify_events` 让 Spring Boot 自动开启 Redis 的
keyspace notifications（用于会话过期事件）。**如果 Redis 禁止 `CONFIG` 命令**
（很多托管服务如此），改为：

```yaml
spring.session.redis.configure-action: none
```

并在 Redis 侧手动设置：

```
notify-keyspace-events Egx
```

不配置这项，会话过期事件收不到，但会话本身仍可正常读写。

## 其他必须一起做的事

1. **同域名与 Cookie**：`server.servlet.session.cookie.domain: civer.cn` 让子域共享
   会话 Cookie。多实例前请确认认证中心与各子系统都在该域下。
2. **Issuer 固定**：`app.base-url` / `APP_BASE_URL` 必须是统一的对外地址
   （如 `https://tidp.civer.cn`），不能是各实例自己的内网地址，
   否则 `iss` 不一致会让 logout_token 验签失败。
3. **反向代理**：`server.forward-headers-strategy` 需按实际网关设置，
   保证后端拿到的是外部 HTTPS 地址。
4. **密钥表**：`oauth2_signing_key` 由 Flyway 建立，所有实例连同一个库；
   首次启动的实例生成密钥，后续实例直接复用（并发启动已处理）。

## 验证清单

- [ ] 两个实例都启动后，登录一次，把请求轮流打到不同实例，会话都有效
- [ ] 在实例 A 登录后，在实例 B 用同一账号登录，A 应被挤下线（验证 `maximumSessions(1)`）
- [ ] 在实例 A 新增/修改客户端，立即在实例 B 触发登出跳转白名单校验，应生效
- [ ] 重启任一实例，已登录用户不掉线、已签发令牌仍可验签
- [ ] 全局登出后，所有实例上的会话都被清除

## 回滚

去掉上述环境变量即回到单机模式。不需要改代码、不需要改数据库。
