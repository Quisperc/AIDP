# 子系统接入 SSO 规范

> 本文件是 Spring Boot 子系统接入的唯一权威说明，按下面步骤即可让一个新的 Spring Boot 应用接入认证中心。
> 认证中心自身的登录/同意页是服务端渲染的，不参与本规范；子系统可以是任何技术栈，
> 只要走标准 OIDC 授权码流程。
>
> **不是 Spring Boot（Node / Python / Go / PHP / 桌面端）？** 先看
> [`外部系统接入.md`](外部系统接入.md)：那份讲怎么从 discovery 拿端点、用 curl 验证，
> 以及任意语言的授权码 + PKCE 最小流程。本文只讲 Spring Boot 侧的接入与退出。
>
> 认证中心**不提供任何私有登出协议**：没有 `logout_token` 推送、没有自研回调端点。
> 退出只用 OIDC RP-Initiated Logout 与 RFC 7009 Token Revocation 两个标准机制。

---

## 一、接入前：先在认证中心注册客户端

子系统必须先被注册，否则认证中心会拒绝授权请求并把用户导到错误页。

- 入口：管理台 `https://idp.civer.cn/admin/clients` → 「注册客户端」（需 `ROLE_ADMIN`）
- 注册完把 `client_id` / `client_secret` 交付给子系统，通过环境变量注入，不要写进仓库

注册时需要提供：

| 字段 | 说明 | 示例 |
|---|---|---|
| `clientId` | 全局唯一，建议与子系统同名 | `my-app` |
| `clientSecret` | 子系统侧需配置同样的值 | 随机生成，勿用弱口令 |
| `redirectUri` | 回调地址，**必须与子系统实际发起登录时的 `redirect_uri` 完全一致，含查询参数** | `https://app.civer.cn/login/oauth2/code/oidc-client` |
| `postLogoutRedirectUri` | 登出后回跳地址，须逐字符匹配 | `https://app.civer.cn/login` |
| `clientName` | 展示在授权同意页 | `我的应用` |
| `requirePkce` | 是否强制 PKCE，**默认开启，公网应用不要关** | `true` |

`redirectUri` 支持填多条（英文逗号分隔），用于区分不同回调（例如按 `?method=` 参数区分）。
**删除客户端会连带清除它的授权与同意记录**，属于不可恢复操作。

## 二、接入步骤

### 1. 加依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-client</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

### 2. 配置 application.yml

```yaml
server:
  port: 8082
  servlet:
    session:
      cookie:
        # 【必改】每个子系统必须取不同的 cookie 名，否则同一浏览器下会话互相覆盖
        name: MYAPP_SESSIONID
        # 不要设 domain：单点登录靠 OIDC 换 code 完成，不靠共享 cookie。
        # 把 cookie 铺到 .civer.cn 只是把本应用的会话暴露给所有子域，并让各子系统的
        # 会话互相干扰（认证中心自己也是 host-only，见 docs/架构说明.md）。
        http-only: true
        same-site: lax

spring:
  config:
    import: optional:file:./application-secret.yml
  security:
    oauth2:
      client:
        registration:
          oidc-client:                 # 注册 ID，下面 {registrationId} 会用到
            provider: auth-server
            client-id: my-app          # 与认证中心注册的一致
            client-secret: ${CLIENT_SECRET}   # 不要写死在配置文件里
            authorization-grant-type: authorization_code
            redirect-uri: "${app.base-url}/login/oauth2/code/{registrationId}"
            scope:
              - openid
              - profile
              - email
        provider:
          auth-server:
            issuer-uri: ${app.auth-server-url}

app:
  auth-server-url: ${APP_AUTH_SERVER_URL:https://idp.civer.cn}
  base-url: ${APP_BASE_URL:https://app.civer.cn}

logging:
  level:
    # 生产务必改回 INFO：DEBUG 会把令牌、请求头等敏感信息写进日志
    org.springframework.security: INFO
```

### 3. 安全配置（SecurityConfig）

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http,
            ClientRegistrationRepository registrations) throws Exception {
        http
            .authorizeHttpRequests(a -> a
                .requestMatchers("/error", "/login").permitAll()
                .anyRequest().authenticated())
            .oauth2Login(oauth2 -> oauth2
                // 不要写 .loginPage("/login")：那会让未登录请求去本应用的 /login，
                // 而不是跳认证中心。默认行为就是重定向到 provider，正合适。
                .userInfoEndpoint(u -> u.oidcUserService(oidcUserService())))
            .logout(logout -> logout
                .logoutUrl("/logout")
                .invalidateHttpSession(true)
                .clearAuthentication(true)
                .deleteCookies("MYAPP_SESSIONID")
                // 标准 OIDC RP-Initiated Logout：跳 discovery 的 end_session_endpoint，
                // 由认证中心吊销令牌与同意，再按已注册的 post_logout_redirect_uri 回跳。
                .logoutSuccessHandler(oidcLogoutSuccessHandler(registrations)));
        return http.build();
    }

    private LogoutSuccessHandler oidcLogoutSuccessHandler(
            ClientRegistrationRepository registrations) {
        OidcClientInitiatedLogoutSuccessHandler handler =
                new OidcClientInitiatedLogoutSuccessHandler(registrations);
        handler.setPostLogoutRedirectUri("{baseUrl}/login?logout");
        return handler;
    }

    /** 把 JWT 里的 roles 映射成权限，否则 @PreAuthorize("hasAuthority('ROLE_ADMIN')") 不生效 */
    private OAuth2UserService<OidcUserRequest, OidcUser> oidcUserService() {
        var delegate = new OidcUserService();
        return req -> {
            var user = delegate.loadUser(req);
            var authorities = new HashSet<GrantedAuthority>();
            List<String> roles = user.getClaimAsStringList("roles");
            if (roles != null) {
                roles.forEach(r -> authorities.add(new SimpleGrantedAuthority(r)));
            }
            authorities.addAll(user.getAuthorities());
            return new DefaultOidcUser(authorities, user.getIdToken(), user.getUserInfo());
        };
    }
}
```

> 只想退出本应用、不动认证中心会话时，把 `logoutSuccessHandler` 换成
> `logoutSuccessUrl("/login?logout")` 即可（本地清 cookie）。两种语义按产品需要二选一。

### 4. 退出与令牌撤销（只用标准端点）

| 目标 | 标准做法 | 谁发起 |
|---|---|---|
| 只退出本应用 | 清本地会话即可，IdP 完全不参与 | 本应用后端 |
| 退出本应用 + 让 IdP 全局退出 | `OidcClientInitiatedLogoutSuccessHandler` 跳 `/connect/logout`（带 `id_token_hint`、已注册的 `post_logout_redirect_uri`） | 浏览器 |
| 让某个令牌立即失效 | `POST /oauth2/revoke`（RFC 7009），带 `client_id`/`client_secret` 与 `token` | 本应用后端 |

认证中心的全局退出会删除该用户的全部 `oauth2_authorization_consent` 与
`oauth2_authorization`（即吊销 access / refresh / id token），**不向子系统推送任何私有登出消息**。
因此子系统内的本地会话需要按上面第一/二行自行结束；未主动结束时，它会随
access token 失效或本地会话超时自然退出。认证中心不保证「其它系统立刻显示已下线」，
也不要把这个现象当成故障。

## 三、常见坑

| 现象 | 原因 |
|---|---|
| 登录后立刻掉线 / 会话互相挤掉 | 两个子系统用了相同的 session cookie name |
| 授权页报「客户端未注册」 | `redirect_uri` 与注册值不一致（含 `?` 后的参数） |
| 退出后其它应用仍显示在线 | 各应用维护自己的本地会话，需各自实现 RP-Initiated Logout；IdP 只负责吊销令牌 |
| `@PreAuthorize` 不生效 | 缺少 `@EnableMethodSecurity`，或没做 roles 映射 |
| 首屏很慢 | 检查是否引用了 fonts.googleapis.com 等境外资源 |

## 四、接入自检清单

- [ ] 已在认证中心注册客户端，`redirect_uri` 与实际请求完全一致
- [ ] 本地账号按 `(iss, sub)` 关联（`sub` 为不可变 UUID），不用用户名/邮箱做唯一键
- [ ] 需要邮箱时请求 `email` scope，并检查 `email_verified` 后再使用
- [ ] `client-secret` 走环境变量或 `application-secret.yml`（已 gitignore）
- [ ] session cookie name 与其它子系统不重复
- [ ] 退出走标准 `/connect/logout` + 已注册的 `post_logout_redirect_uri`
- [ ] 做了 roles 映射，且启动了 `@EnableMethodSecurity`
- [ ] 生产环境 `logging.level.org.springframework.security` 为 `INFO`
- [ ] 前端没有引用境外 CDN / 字体资源
