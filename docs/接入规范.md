# 子系统接入 SSO 规范

> 原 `client-template` 模块已移除。本文件是唯一权威的接入说明，
> 按下面的步骤操作即可让一个新的 Spring Boot 应用接入认证中心。
> 参考实现可直接对照 `client-usermanage`（管理后台，本身就是按这套规范接入的）。

---

## 一、接入前：先在认证中心注册客户端

子系统必须先被注册，否则认证中心会拒绝授权请求并把用户导到错误页。

- 入口：认证中心管理后台 → 客户端管理（`/admin/clients`，需 `ROLE_ADMIN`）
- 或直接调用认证中心接口 `POST /api/clients`（同样需管理员权限）

注册时需要提供：

| 字段 | 说明 | 示例 |
|---|---|---|
| `clientId` | 全局唯一，建议与子系统同名 | `my-app` |
| `clientSecret` | 子系统侧需配置同样的值 | 随机生成，勿用弱口令 |
| `redirectUri` | 回调地址，**必须与子系统实际发起登录时的 `redirect_uri` 完全一致，含查询参数** | `https://app.civer.cn/login/oauth2/code/oidc-client` |
| `postLogoutRedirectUri` | 登出后回跳地址 | `https://app.civer.cn/login` |
| `clientName` | 展示在授权同意页 | `我的应用` |
| `requirePkce` | 是否强制 PKCE，**默认开启，公网应用不要关** | `true` |

`redirectUri` 支持填多行（换行分隔），用于区分不同回调（例如按 `?method=` 参数区分）。

## 二、接入步骤

### 1. 加依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-client</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
<!-- 校验 logout_token 需要 -->
<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-oauth2-jose</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

### 2. 配置 application.yml

```yaml
server:
  port: 8082
  servlet:
    session:
      cookie:
        # 【必改】每个子系统必须取不同的 cookie 名，否则同域下会话互相覆盖
        name: MYAPP_SESSIONID
        # 跨子域共享会话，实现一次登录全站通行
        domain: civer.cn

spring:
  config:
    import: optional:file:./application-secret.yml
  security:
    oauth2:
      client:
        registration:
          oidc-client:                 # 注册 ID，下面 {registrationId} 会用到
            provider: auth-server
            client-id: my-app          # 与认证中心注册的一致
            client-secret: ${CLIENT_SECRET}   # 不要写死在配置文件里
            authorization-grant-type: authorization_code
            redirect-uri: "${app.base-url}/login/oauth2/code/{registrationId}"
            scope:
              - openid
              - profile
        provider:
          auth-server:
            issuer-uri: ${app.auth-server-url}

app:
  auth-server-url: ${APP_AUTH_SERVER_URL:https://tidp.civer.cn}
  base-url: ${APP_BASE_URL:https://app.civer.cn}

logging:
  level:
    # 生产务必改回 INFO：DEBUG 会把令牌、请求头等敏感信息写进日志
    org.springframework.security: INFO
```

### 3. 安全配置（SecurityConfig）

三个不可省略的部分：

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http,
            ClientRegistrationRepository registrations) throws Exception {
        http
            .authorizeHttpRequests(a -> a
                .requestMatchers("/error", "/login").permitAll()
                // 认证中心的后端登出回调不带 CSRF Token，必须放行
                .requestMatchers("/api/sso-logout").permitAll()
                .anyRequest().authenticated())
            .csrf(csrf -> csrf.ignoringRequestMatchers("/api/sso-logout"))
            .oauth2Login(oauth2 -> oauth2
                .loginPage("/login")
                .userInfoEndpoint(u -> u.oidcUserService(oidcUserService())))
            .logout(logout -> logout
                .logoutUrl("/logout")
                .invalidateHttpSession(true)
                .clearAuthentication(true)
                .deleteCookies("MYAPP_SESSIONID")
                // 退到认证中心撤销本次授权同意，再回跳本应用登录页
                .logoutSuccessUrl(authServerUrl()
                    + "/oauth2/revoke-consent?client_id=my-app&redirect_uri="
                    + urlEncode(baseUrl + "/")))
            // 必须注册 SessionRegistry，否则后端登出找不到要失效的会话
            .sessionManagement(s -> s
                .maximumSessions(1)
                .expiredUrl("/")
                .sessionRegistry(sessionRegistry()));
        return http.build();
    }

    @Bean
    public SessionRegistry sessionRegistry() {
        return new SessionRegistryImpl();
    }

    /** 把 JWT 里的 roles 映射成权限，否则 @PreAuthorize("hasAuthority('ROLE_ADMIN')") 不生效 */
    private OAuth2UserService<OidcUserRequest, OidcUser> oidcUserService() {
        var delegate = new OidcUserService();
        return req -> {
            var user = delegate.loadUser(req);
            var authorities = new HashSet<GrantedAuthority>();
            List<String> roles = user.getClaimAsStringList("roles");
            if (roles != null) {
                roles.forEach(r -> authorities.add(new SimpleGrantedAuthority(r)));
            }
            authorities.addAll(user.getAuthorities());
            return new DefaultOidcUser(authorities, user.getIdToken(), user.getUserInfo());
        };
    }
}
```

### 4. 接收后端登出（Back-Channel Logout）

认证中心在全局登出时会向每个已注册客户端推送 `logout_token`。
子系统必须暴露 `POST /api/sso-logout`，否则用户在 A 系统登出后，B 系统的会话仍然存活。

```java
@RestController
public class SsoLogoutController {

    private final SessionRegistry sessionRegistry;

    @Value("${spring.security.oauth2.client.provider.auth-server.issuer-uri}")
    private String issuerUri;

    @Value("${spring.security.oauth2.client.registration.oidc-client.client-id}")
    private String clientId;

    @PostMapping("/api/sso-logout")
    public String ssoLogout(@RequestParam(name = "logout_token", required = false) String token) {
        if (token == null) {
            return "Missing logout_token";
        }
        try {
            // decoder 要复用，每次 new 会丢弃 JWKS 缓存，导致每次登出都重新拉密钥集
            Jwt jwt = decoder(issuerUri + "/oauth2/jwks").decode(token);
            if (!jwt.getAudience().contains(clientId)) {
                throw new IllegalStateException("Invalid audience");
            }
            if (!jwt.getIssuer().toString().replaceAll("/$", "").equals(issuerUri.replaceAll("/$", ""))) {
                throw new IllegalStateException("Invalid issuer");
            }
            expireUserSessions(jwt.getSubject());
            return "Logged out";
        } catch (Exception e) {
            return "Bad Request";
        }
    }
    // expireUserSessions: sessionRegistry.getAllPrincipals() 里找出同名主体，逐个 expireNow()
}
```

> `logout_token` 的推送地址由认证中心根据客户端 `redirect_uris` 的 **host + 端口** 拼上
> `app.sso.client-logout-path`（默认 `/api/sso-logout`）得出，
> 所以该端点的路径不要改，且必须与注册回调同域同端口。

## 三、常见坑

| 现象 | 原因 |
|---|---|
| 登录后立刻掉线 / 会话互相挤掉 | 两个子系统用了相同的 session cookie name |
| 授权页报「客户端未注册」 | `redirect_uri` 与注册值不一致（含 `?` 后的参数） |
| 登出后其它系统仍在线 | 没实现 `/api/sso-logout`，或没注册 `SessionRegistry` |
| `@PreAuthorize` 不生效 | 缺少 `@EnableMethodSecurity`，或没做 roles 映射 |
| 后端登出回调 403 | `/api/sso-logout` 没放行 / 没加 CSRF 忽略 |
| 首屏很慢 | 检查是否引用了 fonts.googleapis.com 等境外资源 |

## 四、接入自检清单

- [ ] 已在认证中心注册客户端，`redirect_uri` 与实际请求完全一致
- [ ] `client-secret` 走环境变量或 `application-secret.yml`（已 gitignore）
- [ ] session cookie name 与其它子系统不重复
- [ ] 实现了 `POST /api/sso-logout` 并注册了 `SessionRegistry`
- [ ] 做了 roles 映射，且启动了 `@EnableMethodSecurity`
- [ ] 生产环境 `logging.level.org.springframework.security` 为 `INFO`
- [ ] 前端没有引用境外 CDN / 字体资源
