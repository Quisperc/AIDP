# 故障复盘

> 已发生的线上问题，按「现象 → 根因 → 修复 → 教训」记录。
> 目的不是存档，而是让同类问题第二次出现时能 5 分钟内定位。
> 完整时间线原文见 `docs/archive/2026-11-03-上线记录与复盘原文.md`。

## 1. 管理接口全部 500

**现象**：`admin.civer.cn` 页面正常，但 `/admin/users`、`/admin/clients` 全部 500。

**根因**：Spring Security 对已认证用户把 `OAuth2AuthorizedClient`（access/refresh token）
存在**应用级内存**里，不在 HttpSession 中。会话迁到 Redis 后，重启管理端只清空了内存里的
token，Redis 里的会话还在——用户「看起来仍登录」，服务端却取不到 token；转发调用认证中心
没有 `Authorization` 头 → 401 → 异常冒泡成 500。

**修复**：三层。

1. `RedisOAuth2AuthorizedClientService`：把 token 拆成字符串字段存 Redis Hash，
   读取时用 `ClientRegistrationRepository` 重新组装对象（不序列化整个对象图）。
   Spring Security 7 起 `OAuth2AuthorizedClient` 已是具体类，`DefaultOAuth2AuthorizedClient` 已移除。
2. 取令牌走统一拦截器（`AuthServerHttpClientConfig`），并新增 `app.auth-server-api-url`
   让转发调用可以走容器内网，绕开公网 CDN 对 `Authorization` 头的处理。
3. `ClientApiExceptionHandler` 把下游 401/403/409 原样透传，不再一律 500。

**教训**：**会话共享 ≠ 状态共享**。迁 Session 到 Redis 时，任何存在进程内存里的
用户态数据都要一起迁移，否则会出现「半登录」这种最难查的状态。

## 2. 500 修好后变 403

**现象**：token 里明明有 `roles: [ROLE_ADMIN]`，`/api/users` 仍返回 403。

**根因**：`TokenConfig.jwtTokenCustomizer()` 确实把角色写进了 `roles` claim，但
`.oauth2ResourceServer(jwt(withDefaults()))` 用的默认 `JwtAuthenticationConverter`
**只认 `scope`/`scp`**，把 `roles` 完全忽略。于是服务端判不出权限，
方法级 `@PreAuthorize("hasAuthority('ROLE_ADMIN')")` 一律拒绝。

**修复**：自定义 `JwtAuthenticationConverter`，把 `SCOPE_*` 与 `roles` 合并成 authorities，
并接入 `oauth2ResourceServer`。已签发的 token 立即生效，无需重新登录。客户端侧
`oidcUserService()` 有同样的问题，一并补上。

**教训**：JWT 里「写进去」和「读出来」是两件事，两端都要有显式映射。
**不要靠删掉 `ROLE_ADMIN` 注解来"解决" 403**——`AdminApiAuthorizationTest` 会立刻抓到
普通用户变成 200 的安全回归。

## 3. CORS 拒绝 `admin.civer.cn`

**现象**：前端域名换成正式域名后，所有接口被 CORS 拦截（预检失败）。

**根因**：后端的 `CORS_ALLOWED_ORIGINS` 还指向 EdgeOne 临时预览域名。

**修复**：改成正式域名并重启容器。改域名是联动操作：`CORS_ALLOWED_ORIGINS`、
`FRONTEND_URL`、前端 `.env.production` 三处必须同时改。

## 4. `um.civer.cn` 静态资源 403 / MIME 为空

**现象**：切换瞬间 `/assets/*` 返回 403 或 `Content-Type` 为空。

**根因**：CDN 缓存了切换窗口内的失败响应。

**修复**：确认源站 200 后在 EdgeOne 控制台刷新缓存；浏览器端 Ctrl+Shift+R。

**教训**：切换后先验 `curl` 的 MIME，不要只看浏览器是否「能打开」。

## 5. `idp.civer.cn` 布局错乱

**现象**：登录/同意/错误/成功页整页滚动、卡片被撑爆。

**根因**：这些页面的图标是内联 SVG，`hig.css` 未限制尺寸，SVG 默认按 `300×150` 渲染；
同时 `page-main` 的 `min-height:100vh` 与独立页脚叠加，超出视口。

**修复**：`hig.css` 中限制 SVG 尺寸，并把布局改为 flex column。

**教训**：内联 SVG 必须显式给 `width/height`，否则视口单位一改就崩。

## 6. `Unexpected token '<', "<!DOCTYPE"... is not valid JSON`

**现象**：前端所有接口报 JSON 解析失败。

**根因**：部署的是**旧版产物**——`API_BASE` 为空，`fetch('/api/me')` 打到前端自己域名，
被 EdgeOne 的 SPA 回退接住返回了 `index.html`。
触发原因是部署工具的 `workspacePath` 与 `builtFolderPath` 指到了 `frontend/` 而不是纯产物目录，
工具复用了 `.edgeone/` 缓存里的旧产物，把新构建覆盖掉了。

**修复**：干净构建 → `cp dist/index.html dist/404.html` → 复制到独立 `pages-out/` →
部署时两个参数**都指向 `pages-out`**。构建参数固化进 `.env.production`，不再靠命令行传。

**教训**：构建产物与构建参数都要可复现。「能部署成功」和「部署的是新代码」是两件事，
必须用 `curl` 抓产物里的 JS 再 grep 一次特征串来验证。

## 7. Redis 模式下全局登出广播失效

**现象**：开启 `SESSION_STORE=redis` 后，全局登出只清掉当前系统，其它子系统仍在线。

**根因**：`SsoLogoutController` 原先遍历 `SessionRegistry.getAllPrincipals()`，
而 `SpringSessionBackedSessionRegistry` 明确不支持该方法（抛异常被吞掉）。

**修复**：改用 `FindByIndexNameSessionRepository`
按 `PRINCIPAL_NAME_INDEX_NAME` 索引直接查该用户的会话，精确且不依赖全量遍历。
这也是 `repository-type: indexed` 必须配置的原因。

**教训**：换 Session 实现时，要检查所有依赖 `SessionRegistry` 语义的地方，
尤其是「不支持」而不是「未实现」的方法——它不会编译报错，只会在运行时静默失效。

## 8. 权限注解静默失效 + 开放重定向（上线前审查发现）

**现象**：无外部表现，属于静态审查发现。

**根因**：

1. 认证中心缺 `@EnableMethodSecurity`。Spring Security 6/7 默认不启用方法级安全，
   所有 `@PreAuthorize` 静默不生效，任意登录用户可创建管理员、改他人密码、删客户端；
2. `/oauth2/revoke-consent` 直接 `redirect:` 请求里的 `redirect_uri`，零校验，可被用于钓鱼。

**修复**：补注解；`redirect_uri` 复用 `SsoLogoutService.isAllowedLogoutRedirect()`
的 host 白名单，不合法就退回 `/`。

**教训**：安全注解失效不会报错，只会不生效。凡是「加了注解就以为安全」的地方，
都要有一条测试能从外部证明它**拒绝**了什么（`AdminApiAuthorizationTest`、
`OpenRedirectSecurityTest` 就是为此存在的）。
