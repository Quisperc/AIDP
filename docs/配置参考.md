> [`docs/部署与运维.md`](部署与运维.md)（发版与排障），当前 1Panel 服务器侧约定见 [`deploy/README.md`](../deploy/README.md)。

## 一、配置来源与优先级

Spring Boot 从高到低依次读取：

| 优先级 | 来源 | 本项目用途 |
|---|---|---|
| 1 | 命令行参数 `--key=value` | 临时覆盖、单机调试 |
| 2 | 环境变量 / `SPRING_APPLICATION_JSON` | **唯一推荐方式**，部署与本地开发都用它 |
| 3 | jar 内 `application.yml` | 静态默认值、结构定义 |
| 4 | 代码内默认值 | 兜底 |

**本项目不引入任何自定义外部配置文件。** 没有 `spring.config.import`，也不读同目录
`application-secret.yml`。

> 注意措辞：这里说的是「不引入自定义配置源」，不是「Boot 完全不会读磁盘」。
> Spring Boot 的默认搜索路径仍包含工作目录的 `application.yml` 与 `config/application.yml`
> （框架内置行为，删掉 `spring.config.import` 也关不掉）。因此**工作目录里不要放这两个标准文件名**；
> `application-secret.yml` 属于非标准名字，移除 import 后已彻底失效，放着也不会被读。

> ⚠️ 历史坑：早期用 `spring.config.import: optional:file:./application-secret.yml` 放本地
> 差异配置，结果是同目录里一个遗留文件就能静默改写 `spring.datasource.*`、`issuer`。
> 更麻烦的是它**优先于 `application.yml` 里的 `${DB_URL}` 占位符**——也就是说
> `DB_URL` 环境变量盖不过它，只有直接写 `SPRING_DATASOURCE_URL` 这种同名属性才行，
> 排查时几乎想不到。2026-11-04 生产配置错乱即由此引起，因此彻底移除。
>
> 需要隐藏配置时用环境变量（`.env` + `set -a; source .env`），或
> `--spring.config.additional-location=file:/path/outside/repo.yml` 显式指定仓库外路径，
> 不要让「工作目录里随便一个文件」参与配置。

`app.base-url` 与 OIDC `issuer` 的关系：`issuer: ${app.base-url}`，而
`app.base-url: ${APP_BASE_URL:http://127.0.0.1:8080}`。所以只设 `APP_BASE_URL` 即可，
不要再去别处单独写 `issuer`，两处不一致会导致 id_token 校验失败。

## 二、环境变量完整表

### 2.1 必需

| 变量 | 对应属性 | 默认值 | 说明 |
|---|---|---|---|
| `DB_URL` | `spring.datasource.url` | `jdbc:postgresql://localhost:5432/authdb` | PostgreSQL JDBC 地址 |
| `DB_USERNAME` | `spring.datasource.username` | `username` | 数据库账号 |
| `DB_PASSWORD` | `spring.datasource.password` | 空 | **必须显式提供**；主配置不留弱默认口令 |
| `APP_BASE_URL` | `app.base-url` → `issuer` | `http://127.0.0.1:8080` | 生产必须是**对外 HTTPS 地址**，如 `https://idp.civer.cn` |
| `REDIS_HOST` | `spring.data.redis.host` | `localhost` | 默认形态下必填（见第四节形态 A） |
| `REDIS_PASSWORD` | `spring.data.redis.password` | 空 | 按 Redis 实例配置 |

## 三、静态配置（jar 内 `application.yml`，一般不用改）

| 段 | 值 | 说明 |
|---|---|---|
| `server.forward-headers-strategy` | `native` | 识别反代 `X-Forwarded-*`，否则 issuer/跳转会带内网地址 |
| `server.servlet.session.cookie` | `AUTH_SESSIONID` / http-only / `SameSite=Lax` / **不设 domain** | host-only，避免把 IdP 会话暴露给所有子域 |
| `spring.session.data.redis.namespace` | `aidp:auth` | 共享 Redis 上与其它应用隔离 |
| `spring.session.data.redis.repository-type` | `default` | 不需要按 principal 索引会话 |
| `spring.session.data.redis.configure-action` | `none` | 共享 Redis：应用不 `CONFIG SET` 改全局配置 |
| `spring.cache.cache-names` | `loginAttempts` | `simple` 类型只会创建声明过的缓存 |
| `spring.data.redis.timeout` / `connect-timeout` | `3s` / `3s` | |
| `spring.sql.init.mode` | `never` | 不再走 `schema.sql` |
| `spring.flyway.baseline-on-migrate` | `false` | 所有库都由 Flyway 从零管理 |
| `management.endpoints.web.exposure.include` | `health,info` | 不暴露 env/beans（`env` 会泄露配置值） |
| `management.endpoint.health.show-details` | `when-authorized` | 匿名只返回 UP/DOWN |
| `app.footer.*` | 备案号 | 见 `application.yml` |

## 四、三种运行形态

### 形态 A（默认、生产推荐）：Redis 会话 + Redis 缓存

classpath 上有 `spring-boot-starter-session-data-redis`，**会话自动存 Redis**；
`CACHE_TYPE=redis` 让登录失败计数也共享。

```dotenv
DB_URL="jdbc:postgresql://<db-host>:5432/<db>"
DB_USERNAME="<user>"
DB_PASSWORD="<strong-password>"
APP_BASE_URL="https://idp.civer.cn"
CACHE_TYPE="redis"
REDIS_HOST="<redis-host>"
REDIS_PORT="6379"
REDIS_PASSWORD="<redis-password>"
APP_BOOTSTRAP_SEED_DEMO_USERS="false"
```

**Redis 侧要求**：`notify-keyspace-events` 含 `Egx`（`CONFIG GET notify-keyspace-events` 应返回
类似 `gxE`）。`configure-action: none` 表示由 Redis 侧统一配置，应用不改全局设置。
共享实例上 `namespace=aidp:auth` 必须与其它应用区分，否则会话串键。

验证：访问 `/login` 后 Redis 应出现 `aidp:auth:sessions:<uuid>`；`/actuator/health` 为 UP。

### 形态 B：无 Redis，单机直接跑 jar

**Redis 不是框架强制依赖**，只是当前默认选择。三个开关一起用即可完全不碰 Redis：
排除会话自动配置、缓存回本地、关掉 Redis 健康探针。

```bash
java -jar Auth-Server.jar \
  --spring.autoconfigure.exclude=org.springframework.boot.session.data.redis.autoconfigure.SessionDataRedisAutoConfiguration \
  --spring.cache.type=simple \
  --management.health.redis.enabled=false
```

等价的环境变量写法（适合容器）：

```dotenv
SPRING_AUTOCONFIGURE_EXCLUDE=org.springframework.boot.session.data.redis.autoconfigure.SessionDataRedisAutoConfiguration
CACHE_TYPE=simple
MANAGEMENT_HEALTH_REDIS_ENABLED=false
```

此时 `HttpSession` 回到 Servlet 容器本地，会话 Cookie 是本地 session id；**重启容器会掉线**，
且不能水平扩容。仅适合本地开发、演示或单实例且可接受重启重登的场景。

> 2026-11-04 已在生产同版本 jar 上实测：health UP、`/login` 200、Redis 键数不变、0 ERROR。

### 形态 C：多实例 / 重启不掉线

在形态 A 基础上，所有实例必须共享：同一个 PostgreSQL 库（`issuer`、签名密钥、客户端注册表
都在库里）、同一个 Redis、相同的 `APP_BASE_URL`。反代无需 sticky session（会话在 Redis）。
`CACHE_TYPE=redis` 让登录限流在所有实例上合计计数。

## 五、`CACHE_TYPE=simple` 到底影响什么

| 层 | 受 `CACHE_TYPE` 影响吗 | 说明 |
|---|---|---|
| HTTP 会话 | **否** | 由 session starter 决定，始终走 Redis（除非用形态 B 排除自动配置） |
| 登录失败计数 | 是 | `simple` → `ConcurrentMapCacheManager` 进程内计数；多实例时每个实例各算各的，限流阈值被放大 |
| Redis 健康探针 | 否 | classpath 有 `spring-boot-starter-data-redis` 就会注册；Redis 挂了 health 变 DOWN（形态 B 需显式关掉） |

只把 `CACHE_TYPE` 改成 `simple` **不会**让 Redis 变成可选：会话仍写 Redis，Redis 不可用照样登录不了。
要彻底去掉 Redis，必须按形态 B 排除会话自动配置。

## 六、数据库与 Flyway

- PostgreSQL 14+（生产 18.6）；测试用 H2 的 `MODE=PostgreSQL` 跑同一批迁移。
- 迁移脚本：`V1` 基础表 / `V2` 审计表 / `V3` 账号资料与稳定 `sub`。
- **已应用的迁移脚本只读**：Flyway 校验整个文件的 checksum，改一句注释都会让启动失败
  （v2.8.0 事故）。要改 schema 只能新增版本化迁移。
- `V3` 是破坏性迁移（清空授权/同意、规范化 scopes），上线前必须备份。
- 签名密钥存 `oauth2_signing_key` 表，多实例共享同一把；密钥损坏时启动直接失败，不静默重建。

## 七、健康检查与日志

- `GET /actuator/health`：匿名只返回 `{"status":"UP"}`；`liveness` / `readiness` 探针已开启。
- 仅暴露 `health,info`；不要为了排障临时放开 `env`（会泄露口令）。
- 日志前缀：`[users]`、`[clients]`、`[sso-logout]`、`[flyway]` 便于检索。
- 生产不要开 `SHOW_SQL=true`，SQL 日志会带参数值。

## 八、常见配置错误

| 现象 | 原因 | 处理 |
|---|---|---|
| health DOWN、日志 `Unable to connect to localhost:6379` | 环境变量没进 Java 进程 | 见下：1Panel `.env` 坑 |
| 数据源指向了意料之外的库 | 工作目录里残留 `application-secret.yml`（旧版本会用 `spring.config.import` 读它），其值优先于 `${DB_URL}`；或工作目录里有 `application.yml` / `config/application.yml`（Boot 默认会读） | 删掉该文件；现版本不读 `application-secret.yml`，但标准文件名仍会被框架加载 |
| Redis 里出现 `spring:session:*` 而不是 `aidp:auth:*` | 用了旧前缀 `spring.session.redis.namespace` | 改成 `spring.session.data.redis.namespace` |
| 设了 `SESSION_STORE=redis` 但会话仍在本地 | Boot 4 已移除该属性，且只引原生模块不带自动配置 | 用 `spring-boot-starter-session-data-redis` |
| `iss` 校验失败 / 跳转带内网地址 | `APP_BASE_URL` 没设，或反代没传 `X-Forwarded-*` | 设对外 HTTPS 地址；反代补齐转发头 |
| 多实例下登录限流形同虚设 | `CACHE_TYPE=simple`，各实例独立计数 | 设 `CACHE_TYPE=redis` |
| 1Panel 里改了 Java 版本后所有配置失效 | 1Panel 重写 `.env` 时把 `export` 去掉，而 `run.sh` 只做 `source`，变量不会传给子进程 | 见 `deploy/README.md`：`run.sh` 用 `set -a` 包裹 `source` |

## 九、1Panel Java 运行环境的特殊点（当前生产）

`/opt/1panel/runtime/java/idp_auth_server/.env` 被 bind mount 到容器 `/.env`，
`run.sh` 被挂载为 `/run.sh`，内容是 `source /.env` 后 `eval $EXEC_SCRIPT`。

1Panel 生成的变量形如 `KEY="value"`，**不带 `export`**；普通 shell 赋值不会传给子进程，
`java -jar` 一个环境变量都读不到（2026-11-04 实测导致 Redis 回落 localhost、health DOWN）。
因此该目录下的 `run.sh` 必须用 `set -a` 包裹 `source`：

```bash
#!/bin/bash
set -a
source /.env
set +a
eval $EXEC_SCRIPT
```

升级 Java 版本或在面板里编辑运行环境后，1Panel 可能重写 `.env` / `run.sh`，
**改完务必核对** `docker exec idp_auth_server sh -c 'tr "\0" "\n" < /proc/<java-pid>/environ'`
里是否仍有 `DB_*` / `REDIS_*` / `APP_BASE_URL`，并用 `/actuator/health` 复核。
