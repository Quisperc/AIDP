## 二、EdgeOne 前端与 DNS

### 当前访问地址（预览用）

https://aidp-admin-console-aildw6lu.edgeone.cool?eo_token=1859454d74a003f18062de58b169bd83&eo_time=1793709109

### 需要配置的 DNS（建议你去配）

**强烈建议绑定 `civer.cn` 的子域**，例如 `admin.civer.cn`。原因：
前端与 `um.civer.cn` 同属 `civer.cn`，属于**同站**，会话 Cookie 不会被第三方
Cookie 策略拦截；若用 `edgeone.cool` 临时域名则是跨站，只能依赖
`SameSite=None; Secure`，部分浏览器仍可能限制。

| 记录类型 | 主机记录 | 记录值 |
|---|---|---|
| CNAME | `admin`（即 admin.civer.cn） | `013c344bef7f6e5e.edgeone.cool.pages.dnsoe5.com` |

> 该值来自当前 Pages 部署域名的 CNAME 链：
> `aidp-admin-console-aildw6lu.edgeone.cool → 013c344bef7f6e5e.edgeone.cool.pages.dnsoe5.com`

**必须先做的两步**（DNS 单独配不会生效）：

1. 在 EdgeOne Pages 控制台 → 项目 `aidp-admin-console` → 域名管理，
   添加自定义域名 `admin.civer.cn`。控制台会给出它要求的 CNAME 值，
   以控制台显示的为准（若与上表不同，用控制台的值）。
2. 按控制台给出的值配 CNAME，等待证书签发与解析生效。

### 配好域名后需要同步更新后端（已完成）

自定义域名 `admin.civer.cn` 生效后，CORS 白名单与登录回跳地址已更新为
`https://admin.civer.cn`（同时保留临时预览域名），并重启了管理端。
当时的报错正是因为白名单还指向临时域名。若再次更换域名，按下面方式更新：

```bash
# 在服务器上编辑 /opt/1panel/runtime/java/idp_user_manage/.env
export CORS_ALLOWED_ORIGINS=https://admin.civer.cn
export FRONTEND_URL=https://admin.civer.cn
# 若域名同站（admin.civer.cn 与 um.civer.cn），建议改回更安全的：
export COOKIE_SAME_SITE=Lax
export COOKIE_SECURE=false
docker restart idp_user_manage
```

同时前端构建产物里的 API 基址已固定为 `https://um.civer.cn`，与前端域名无关，
**不需要重新构建前端**。

## 三、本轮启用的环境变量

写入 `/opt/1panel/runtime/java/idp_*/.env`（`run.sh` 会 `source` 它）：

**auth-server**
```
SESSION_STORE=redis
CACHE_TYPE=redis
REDIS_HOST=1Panel-redis-ghWF
REDIS_PASSWORD=<运行时从 Redis 容器提取>
APP_BASE_URL=https://idp.civer.cn
```

**user-manage**
```
SESSION_STORE=redis
CACHE_TYPE=redis
REDIS_HOST=1Panel-redis-ghWF
REDIS_PASSWORD=<运行时从 Redis 容器提取>
CORS_ALLOWED_ORIGINS=https://aidp-admin-console-aildw6lu.edgeone.cool
FRONTEND_URL=https://aidp-admin-console-aildw6lu.edgeone.cool
COOKIE_SAME_SITE=None
COOKIE_SECURE=true
APP_AUTH_SERVER_URL=https://idp.civer.cn
APP_BASE_URL=https://um.civer.cn
```

去掉这些变量即回到单机模式，无需改代码。

## 四、回退到旧版本

备份清单（后缀 `20261103-201203`）：

```
/home/idp/auth_server/Auth-Server.jar.bak-20261103-201203
/home/idp/user_manage/UserManage-Server.jar.bak-20261103-201203
/opt/1panel/runtime/java/idp_auth_server/.env.bak-20261103-201203
/opt/1panel/runtime/java/idp_user_manage/.env.bak-20261103-201203
```

一键回退：

```bash
TS=20261103-201203
cp /home/idp/auth_server/Auth-Server.jar.bak-$TS     /home/idp/auth_server/Auth-Server.jar
cp /home/idp/user_manage/UserManage-Server.jar.bak-$TS /home/idp/user_manage/UserManage-Server.jar
cp /opt/1panel/runtime/java/idp_auth_server/.env.bak-$TS /opt/1panel/runtime/java/idp_auth_server/.env
cp /opt/1panel/runtime/java/idp_user_manage/.env.bak-$TS /opt/1panel/runtime/java/idp_user_manage/.env
docker restart idp_auth_server idp_user_manage
```

回退后旧版本不认识 Redis 相关环境变量（已从 .env 移除），行为与改造前一致。

## 八、已修复的线上问题

- **CORS 拒绝 admin.civer.cn**：白名单只配了临时预览域名，已补上并重启。
- **um.civer.cn 静态资源 403 / MIME 为空**：切换瞬间 CDN 缓存了失败响应；
  当前所有 `/assets/*` 已验证为 200 且 MIME 正确（`text/css` / `text/javascript`）。
  若浏览器仍报旧错，强刷（Ctrl+Shift+R）或在 EdgeOne 控制台刷新缓存即可。
- **idp.civer.cn 布局乱**：登录/同意/错误/成功页的图标是内联 SVG，
  HIG 样式未限制其尺寸（默认按 300x150 撑爆卡片）；同时 `page-main` 的
  `min-height:100vh` 与独立页脚叠加导致整页滚动。已在 `hig.css` 中限制
  SVG 尺寸并改为 flex column 布局。
